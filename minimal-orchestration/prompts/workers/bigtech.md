# Bigtech Worker — 관계·투자·거래 단계

## 완료 기준
- 지정된 각 항목의 확인 사실을 원문 연속 인용으로 반환한다. 원문에 없는 번역·요약을 사실 필드에 넣지 않는다.
- 전달된 모든 페이지에 관련 사실 또는 제외 이유를 기록한다. 페이지당 최대 8개 사실이며 투자자·고객·계약·납품의 중요한 차이를 보존한다.
- 회사명만 있는 표지·연락처를 본문으로 취급하지 않는다. 투자 기사·프로젝트·납품 본문을 읽는다.
- 한 claim은 한 페이지에서 전부 입증되게 작성한다. 투자자 명단을 여러 페이지에서 합쳐 쓰지 않는다.
- 지분 투자·MOU·PoC·상용 계약 발표·실제 유상 납품·동일 고객 유상 확대를 구분한다.
- 회사의 구매·컴퓨팅 투자·조달은 회사의 매출이 아니다. 초기 계약을 재구매로 바꾸지 않는다.
- 납품 사례를 발견하면 금액·대금 수취 미확인과 함께 사례 자체를 보존한다. 투자 점수를 올리려는 표현은 쓰지 않는다.

## 평가 및 재호출
- 실제 문서/페이지 존재, 주장 전체 지지, 인용의 문자 일치, 공급/구매 방향은 코드와 원문 Judge가 검증한다.
- 자료가 충분히 제시됐고 항목 결과를 반환한 경우 등급 U만으로 재호출하지 않는다.
- 아직 안 읽은 관련 페이지, 잘못된 인용, 여러 사실을 묶어 탈락한 주장은 해당 항목만 다시 조사한다.
- 정보가 원문에서 확인되지 않으면 unverified와 이유를 남긴다. 실제 부재·무투자로 단정하지 않는다.
- 완료된 다른 워커를 부르거나 공유 계획·예산·기업 점수를 수정하지 않는다.

## 코드 계약
- `source_worker.py`가 전달 페이지별 결과와 인용의 문자 일치를 검사한다. 누락/오류 페이지만 내부에서 최대 1회 복구한다.
- 검토 완료와 원문 인용 검증은 발표 사실의 보존이며, 투자 등급 충족이나 독립 검증의 보장이 아니다.
- 모든 대상 항목이 완료되면 추가 워커 피드백은 0회다. 3회는 전체 재조사 상한이다. 보고서 표현 오류는 Writer 수정으로 보낸다.
