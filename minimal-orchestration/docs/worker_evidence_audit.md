# 워커 기준·근거 회수·기업별 출력 점검

이 문서는 **수정 전 초기 감사 기록**이다. 당시에는 오케스트레이션 제어가 동작했지만 근거 회수와 의미 정확성에 아래 결함이 남아 제출본을 교체하지 않았다. 이후 코드 수정·기업별 재실행·현재 원문 대조 결과는 [최신 근거 전달 검증](evidence_flow_fix.md)을 따른다. 아래 수치는 초기 실행의 값이며 최신 결과와 혼합하지 않는다.

숫자는 중복을 포함한 `source_checked_claims` 수이며 전체 사실 회수율이 아니다. 실행별 질문·웹 응답·모델 출력이 달라 인과 효과·비용 절감률로 해석하지 않는다. 세 기업 모두 내용 Judge는 통과했지만 독립 원문 대조에서 위 결함을 찾았다. Judge 통과를 원문 정확성의 보장으로 쓰지 않는다.

## 확인한 코드 원인과 보완

1. **검색 결과의 본문 선택:** MOTOMIND 제품화 질의 상위 4개에 표지·연락처 페이지가 섞였다. `task_evidence.py`로 항목별 카탈로그의 핵심 페이지 실제 본문을 보완한다. 카탈로그 notes는 사실의 근거로 전달하지 않는다.
2. **카탈로그 키 누락:** `load_project_catalog`가 key_pages·related_scorecard_items를 State에 보존하지 않았다. 이를 보존하고 실제 MM-04 PDF의 납품 페이지가 워커 입력으로 전달되는 통합 회귀 검사를 추가했다.
3. **복합 주장 탈락:** 기술·데이터 수단·납품을 한 주장에 묶으면 한 페이지가 전부 지지하지 못해 전체가 버려졌다. MD와 프롬프트에서 한 페이지·한 사실로 분리하도록 했다. 여전히 부분 지지 탈락이 남아 자동 분리·재검증이 추가로 필요하다.
4. **인용 문자 불일치:** 영문 단어의 PDF 줄바꿈 때문에 실제 인용도 탈락했다. 공백만 달라진 경우 원문 연속 구간을 반환한다. 문자·숫자·문장부호·의미 검증은 완화하지 않는다.
5. **잘못된 URL 반복:** 로컬 PDF 경로·미등록 URL을 웹 URL로 실행했다. 등록 URL만 남기고 이미 실패한 요청은 다시 선택하지 않는다. 거절 URL은 Task에 기록한다.
6. **Writer의 U 항목 혼동:** 사용할 수 있는 정확한 U 항목 목록을 별도로 전달한다. 코드 검사는 유지한다.

## 워커별 MD와 실제 실행 연결

[Bigtech](../prompts/workers/bigtech.md) · [Technology](../prompts/workers/technology.md) · [Market](../prompts/workers/market.md)를 실제 프롬프트에 읽어 넣고 파일 SHA256을 워커 출력에 기록한다. 문서만 만들어 두는 방식이 아니다.

MD는 다음 네 가지를 정의한다: 회수해야 할 사실, 허용하는 근거·인용, 완료/미확인 종료 기준, 재호출해야 할 결함. `관련 페이지 전달 + 항목별 명시 응답`은 `source_review_complete`로 기록하되 이는 **전체 의미상 사실의 완전 회수 검사와 다르다.** 이 한계를 숨기지 않는다.

- 기준 충족: 추가 워커 호출 없이 다음 단계.
- 원문 검토 후 미확인: U와 사유 보존, 점수를 얻기 위한 반복 금지.
- 검색/추출/인용 실패: 해당 항목·역할만 피드백. 상한은 3회이며 의무 횟수가 아니다.

테스트에서 모든 역할을 검토하고 등급이 U인 경우 재조사 0회, 시장 역할만 미완료인 경우 시장만 재호출되는 것을 확인했다. 실제 재실행에서도 역할마다 3회 고정 호출하지 않았다. 전체 재계획 카운터 3에는 미선택 항목 조사와 계획 오류도 포함돼 있어, 아직 불필요한 재계획을 더 줄일 여지가 있다.

## 남은 우선 보완

- 원문 핵심 사실과 워커 결과를 비교하는 독립 회수 평가. 정확한 주장만 쓰는 것과 충분한 사실을 찾는 것을 분리한다.
- 부분 지지 주장 중 입증 가능한 단일 사실만 분리하고 다시 원문 검증하는 제한된 복구.
- 납품→유상 납품, 투자자 전체→대기업 계열 VC, 계약 목적→배치 완료 같은 의미 확장을 차단하는 평가·회귀 사례.
- 정해진 역할 중복·작업 ID 충돌을 계획 오류로 버려 재계획 예산을 쓰는 문제.

현재 MD·완료 분기는 개선됐으나, 위 결함이 남아 기업 운영 수준의 보고서 정확성이나 전반적 회수율 개선을 확인했다고 선언하지 않는다.

## 검증 표본

[15개 핵심 원문 위치](../evaluation/retrieval_cases.json)를 실제 PDF 문자와 대조했다. 단일 항목 질의의 dense top4에서 해당 위치를 찾은 표본은 MOTOMIND 0/5, ROBROS 2/5, Figure AI 1/5였다. 관련 카탈로그 핵심 페이지 입력에서는 각각 3/5, 4/5, 5/5였다. 이는 해당 위치의 **입력 포함 여부**이며 실제 워커의 다항목 질의 전체 결과·의미 회수율·보고서 반영률은 아니다. 다른 페이지에 같은 사실이 있으면 의미상 회수는 별도로 판정해야 한다.
