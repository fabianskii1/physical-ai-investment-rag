# 원문 회수·과장 통제·기업 보고서 전달 검증

2026-10-16 수정 및 실제 실행 기록이다. 이전 결함은 [초기 감사](worker_evidence_audit.md)에 보존한다. 작업 이력은 `output/validated-investment-final-20261016/`에 보존하고, 통과한 결과는 `output/submission-live/`에 반영했다.

## 변경한 동작

1. **원문 회수:** 기업 PDF 전체 페이지와 항목별 COMMON 자료를 워커에 전달한다. 모델은 사실 문장을 창작하는 대신 페이지의 줄 구간을 선택한다. 코드가 현재 PDF에서 그 구간의 인용을 만들고 발행자를 붙인다. 페이지별 검토·제외·오류를 기록하며 누락 페이지는 내부에서 최대 1회 복구한다. 회사 발표의 정확한 인용은 독립 입증을 뜻하지 않는다.
2. **의미 확대 차단:** 문단의 인용을 검증 사실에 연결한다. 납품→유상 매출, 투자자 명단 전체→대기업 계열 VC, 계약 목적→배치 완료, 성능 목표→달성 실적 확대를 코드와 원문 Judge로 검사한다. 미확인·자료 부족이라는 실제 한계 설명을 긍정 단정으로 오인한 규칙도 교정했다.
3. **필요한 피드백만 실행:** 완료된 평가항목은 다음 계획에서 제외한다. 한 항목의 추출 오류로 완료한 다른 항목을 다시 열지 않는다. 검토 후 U는 반복 사유가 아니다. 실제 조사 미완료만 해당 워커, 점수 사유 오류는 Judge, 본문 오류는 해당 구역 Writer로 보낸다. 후속 Writer는 결함 없는 구조화 구역을 코드가 보존한다.
4. **확인 사실 보존:** 점수가 U여도 TAS·Master Arm·데이터 검수/라벨링·Index·성능 목표·고장 정보 같은 검증된 사실을 기업 본문에 보존한다. 같은 원문 페이지 문맥만 사용하며 새 조사·채점은 하지 않는다. SDK 설치 버전은 성능 목표로 분류하지 않는다.
5. **최종 전달:** 실제 기업 본문 전체·문단·SHA256·점수·원문을 최종 그래프의 종합·선정 노드에 전달한다. 본문에서 사용한 인용을 종합 근거로 제한하고, 핵심 사실의 원문 ID·실제 최종 문단/발췌와 의미 보존 여부를 같은 품질 Judge에서 검사한다. 점수표·U·공식 선정 조건은 재작성으로 바꿀 수 없다.
6. **중복 입력 제거:** 최종 Judge의 문단별 `assertion_pairs`와 원문 페이지는 유지하고 전체 근거 사전을 다시 전달하던 중복을 제외했다. 이번 입력에서 약 48만 자가 줄었다. 이는 입력 중복 제거량이며 전체 비용·시간 절감률은 측정하지 않았다.

## 기업별 실제 결과

| 기업 | 확인 획득점수 | 확인 / U 배점 | 검증 인용 수 | 품질 | A4 쪽수 |
|---|---:|---:|---:|---|---:|
| MOTOMIND | 23 | 61 / 39 | 83 | 통과·partial | 9 |
| ROBROS | 22.75 | 33 / 67 | 149 | 통과·partial | 10 |
| Figure AI | 48.25 | 66 / 34 | 138 | 통과·partial | 10 |

점수는 원래 100점 배점에서 확인된 항목의 획득점수다. U를 0으로 채우거나 확인 배점만으로 재환산하지 않는다. 검증 인용 수는 중복을 포함하며 전체 사실 회수율이 아니다. 세 기업의 현재 개별 의견은 투자 보류다.

최초 조사 이력은 기업마다 워커 7회다. MOTOMIND는 기술 3·시장 3·빅테크 1회, ROBROS와 Figure AI는 기술 4·시장 2·빅테크 1회다. 초기 호출도 포함한 숫자이며 역할당 3회 고정 실행이 아니다. 이미 완료로 선언된 **평가항목의 재호출은 세 기업 모두 0건**이다. 이후 원문 재검증·재채점·본문/템플릿 복구는 저장된 워커 출력을 사용했으며 새 워커·검색을 실행하지 않았다. 원래 조사 이력과 복구 실행을 구분한다.

## 원문과 본문 독립 대조

생성 프롬프트에 전달하지 않은 [15개 고정 원문 표본](../evaluation/retrieval_cases.json)을 현재 PDF와 대조했다.

- 15개 구절 모두 실제 원문에 존재한다. 검증 인용 자체에 구절이 있는 표본은 14개이고, TAS는 같은 페이지의 검증된 문맥을 포함하면 15개다.
- 기업 본문의 정확한 표본 문서·페이지 인용은 14/15다. ROBROS 데이터 플랫폼은 등록 웹 원문의 동일 구절을 인용했다. 이 대체 출처까지 구분해 세면 15/15이며, 원래 표본 문서 인용 15/15라고 표시하지 않는다.
- 채택된 인용 370개는 현재 원본 페이지의 연속 구간과 일치한다. 이 검사는 인용의 정확성 검사이며 등급 정답·의미상 완전 회수의 보장이 아니다.
- [감사 스크립트](../scripts/audit_evidence_flow.py)는 현재 원문·State·기업 본문·최종 본문의 인용 전달과 해시를 다시 확인한다. 의미 보존은 별도로 원문 Judge와 본문 검토를 사용한다.

## 최종 결과와 복구 이력

[최종 PDF](../output/submission-live/final_investment_report.pdf)는 **Figure AI 조건부 투자·A4 9쪽·상하좌우 20mm**다. 기업별 전문 SHA256과 21항목 점수/사유를 보존했다. Groundedness·중립성·편향 통제와 분석/한계/의견 반영 증거 9개, 핵심 사실 반영 6개가 통과했다. 15개 표본은 최종 본문에서도 등록 원문의 실제 인용에 연결돼 있다. 전체 페이지와 투자 조건 페이지를 렌더링해 잘림·겹침을 확인했다.

새 합성·선정 뒤 본문 수정 1회에서 품질 API 시간 초과가 발생했다. 분석·수정 본문을 보존해 재개했고 2회 추가 수정 뒤 남은 실패는 구 규칙의 “자료가 비어 있다” 오탐이었다. 현재 규칙으로 같은 본문을 재평가한 마지막 실행은 추가 수정 없이 통과했다. **복구 실행을 합친 수정 3회**와 마지막 실행 수정 0회를 구분한다. 이 오탐 때문에 불필요한 Writer 호출이 실제 발생했으며 수정 후 전체 비용 절감 효과를 주장하지 않는다.

[실행 감사](../output/submission-live/final_report.execution_audit.json)는 SDK에서 확인한 세 root의 노드 순서·종료, 시간 초과, 복구 이력을 보존한다. 최신 root는 `01a14365-dc0e-7511-b69d-986555bf9f3c`다. 회귀 검사는 **531개 + 하위 테스트 22개**를 통과했다.

## 재현

```bash
# 실제 새 조사·기업별 품질 평가
.venv/bin/python scripts/check_company_evidence.py --help
# 현재 원문·저장 결과의 전달만 오프라인 대조
.venv/bin/python scripts/audit_evidence_flow.py output/submission-live
# 통과한 기업 결과로 종합·선정·품질·필요한 수정·PDF 실행
.venv/bin/python app.py --combine-reports output/submission-live
```

키는 `.env`에서 읽고 공개 자료에 포함하지 않는다. 저장 분석의 재사용은 회사 보고서·점수·인용·현재 원문 일치 검사를 거치며 품질 판정은 새로 수행한다. 일반적인 의미 회수율·Judge 정답률·전체 비용 절감과 기업 운영 수준의 정확성을 입증한 결과는 아니다. DB 기반 지속 복구와 전체 실행 비용 상한도 추가 구현 대상이다.
